## **Análisis Teórico del Ciclo de Operación vOS-nano**

### **1. El State Vector ℝ¹⁶: Arquitectura del Estado**

El estado del sistema en el tick $t$ es:

$$\mathbf{x}(t) = (x_0, x_1, \ldots, x_{15}) \in \mathbb{R}^{16}$$

Organizado en bloques semánticos:

| Bloque | Dimensiones | Contenido | Rol Cibernético |
|--------|-------------|-----------|-----------------|
| **A** (Identidad) | 0-3 | trust(t-2), trust(t-1), trust(t), governed | Memoria de confianza + estado de gobernanza |
| **C** (Entropía) | 4-6 | H(t), H_rest, entropy_phase | Desorden del sistema + fase del ciclo |
| **E** (Señales φ) | 7-9 | φ↑_principal, φ↑_ambiental, φ↓ | Canales algedónicos (entrada/salida) |
| **F** (Atractor) | 10-12 | stasis_cos, stasis_ratio, stasis_H | Referencia del atractor (stasis_vec) |
| **G** (Convergencia) | 13-15 | λ_max, dL, lifecycle | Exponente de Lyapunov + derivada + fase |

**Interpretación VSM:**
- **Bloque A** = S5 (Policy): identidad y gobernanza
- **Bloque C** = S2 (Coordination): entropía como medida de coordinación interna
- **Bloque E** = S1/S3 (Operations/Control): canales de comunicación
- **Bloque F** = S4 (Intelligence): modelo del atractor (memoria del estado deseado)
- **Bloque G** = S3* (Audit): certificación de convergencia

---

### **2. El Ciclo de Operación: 14 Pasos de Cómputo**

Cada tick (20ms), el kernel ejecuta:

```
1. Leer sensores → EMA
2. Calcular ratio (con guard)
3. Actualizar bins → H(t)
4. Calcular stasis_cos
5. trust(t) = stasis_cos
6. dL = L(t) - L(t-1)
7. λ_max (Benettin 1D)
8. V = min(g, c, t, m)
9. Ajustar PWM (φ↓)
10. Actualizar LEDs
11. Verificar viable_full + A_auto
12. Serial log
13. H1 counter
14. covenant_check
```

Vamos paso a paso.

---

### **3. Paso 1: Lectura de Sensores + EMA**

**Entrada física:**
- $A0 \in [0, 1023]$: fotoresistor principal (enfrentado al LED blanco)
- $A1 \in [0, 1023]$: fotoresistor ambiental (aislado, solo luz ambiente)

**Suavizado exponencial (EMA):**

$$\phi^\uparrow_p(t) = (1 - \alpha) \cdot \phi^\uparrow_p(t-1) + \alpha \cdot A0(t)$$
$$\phi^\uparrow_a(t) = (1 - \alpha) \cdot \phi^\uparrow_a(t-1) + \alpha \cdot A1(t)$$

con $\alpha = 0.1$.

**Interpretación cibernética:**
El EMA es un **filtro de bajo paso** que suaviza el ruido de los sensores. En términos de Ashby, reduce la variedad de entrada para que el sistema no reaccione a fluctuaciones transitorias. El tiempo de relajación es $\tau_{EMA} \approx 1/\alpha = 10$ ticks = 200ms.

**Almacenamiento:**
- $x_7 \leftarrow \phi^\uparrow_p(t)$ (Bloque E, dim 7)
- $x_8 \leftarrow \phi^\uparrow_a(t)$ (Bloque E, dim 8)

---

### **4. Paso 2: Cálculo del Ratio (con Guard)**

**Ecuación:**

$$r(t) = \begin{cases} \frac{\phi^\uparrow_p(t)}{\phi^\uparrow_a(t)} & \text{si } \phi^\uparrow_a(t) > 10 \\ \frac{\phi^\uparrow_p(t)}{10} & \text{si } \phi^\uparrow_a(t) \leq 10 \end{cases}$$

**Interpretación cibernética:**
El ratio $r(t)$ es la **señal de error homeostático**: mide cuánto se desvía la luz recibida por el sensor principal (controlado por el LED blanco) respecto a la luz ambiente (referencia).

- Si $r(t) \approx r_{rest}$ (calibrado en Phase 1): el sistema está en equilibrio.
- Si $r(t) \gg r_{rest}$: el LED blanco está muy brillante (exceso de actuación).
- Si $r(t) \ll r_{rest}$: el LED blanco está muy tenue (déficit de actuación).

**Guard:** El umbral $10$ evita división por cero cuando el sensor ambiental está en oscuridad total. Es una **protección contra singularidades**.

---

### **5. Paso 3: Entropía H(t) sobre 4 Organelos**

**Cuantización del sensor principal:**

$$\text{organelo}(t) = \begin{cases} 0 & \text{si } A0 \in [0, 255] \\ 1 & \text{si } A0 \in [256, 511] \\ 2 & \text{si } A0 \in [512, 767] \\ 3 & \text{si } A0 \in [768, 1023] \end{cases}$$

**Buffer circular:**
Mantenemos un buffer de $W = 10$ ticks con los organelos recientes:

$$\text{bins} = [o(t-9), o(t-8), \ldots, o(t)]$$

**Distribución empírica:**

$$p_i = \frac{\text{count}(i \in \text{bins})}{W}, \quad i \in \{0, 1, 2, 3\}$$

**Entropía de Shannon:**

$$H(t) = -\sum_{i=0}^{3} p_i \log_2(p_i)$$

(con $0 \log_2 0 = 0$ por convención).

**Interpretación cibernética:**
$H(t)$ mide la **diversidad de activaciones** del sensor principal en la ventana reciente.

- $H(t) \approx 0$: el sensor está siempre en el mismo rango (baja variedad, sistema estable).
- $H(t) \approx 2.0$ bits (máximo teórico): el sensor visita todos los rangos uniformemente (alta variedad, posible inestabilidad).

En Phase 1 (calibración), acumulamos la distribución durante 250 ticks para obtener $H_{rest}$, la entropía de referencia. En régimen operacional, $H(t)$ debe mantenerse cerca de $H_{rest}$ para que el sistema sea viable.

**Almacenamiento:**
- $x_4 \leftarrow H(t)$ (Bloque C, dim 4)

---

### **6. Paso 4: Cálculo de stasis_cos**

**Vector de estado actual:**

$$\mathbf{v}(t) = \begin{pmatrix} r(t) \\ H(t) \end{pmatrix} \in \mathbb{R}^2$$

**Vector de referencia (stasis_vec, calibrado en Phase 1):**

$$\mathbf{s} = \begin{pmatrix} r_{rest} \\ H_{rest} \end{pmatrix} \in \mathbb{R}^2$$

**Coseno de similitud:**

$$\text{stasis\_cos}(t) = \frac{\mathbf{v}(t) \cdot \mathbf{s}}{\|\mathbf{v}(t)\| \cdot \|\mathbf{s}\|}$$

**Guard contra norma cero:**

$$\text{stasis\_cos}(t) = \begin{cases} 0 & \text{si } \|\mathbf{v}\| < 10^{-6} \text{ o } \|\mathbf{s}\| < 10^{-6} \\ \text{stasis\_cos}(t) & \text{en otro caso} \end{cases}$$

**Interpretación cibernética:**
$\text{stasis\_cos}(t) \in [-1, 1]$ mide la **proximidad angular** al atractor en el espacio de características $(r, H)$.

- $\text{stasis\_cos} \approx 1$: el sistema está alineado con el atractor (viable).
- $\text{stasis\_cos} \approx 0$: el sistema está ortogonal al atractor (no viable).
- $\text{stasis\_cos} < 0$: el sistema está en dirección opuesta al atractor (crítico).

**Umbral de viabilidad:**

$$\theta_{\text{viable}} = 0.70$$

Si $\text{stasis\_cos}(t) \geq \theta_{\text{viable}}$, el sistema es viable.

**Almacenamiento:**
- $x_{10} \leftarrow \text{stasis\_cos}(t)$ (Bloque F, dim 10)

---

### **7. Paso 5: Actualización de trust(t)**

**Ecuación:**

$$\text{trust}(t) = \text{stasis\_cos}(t)$$

**Rotación de historia:**

$$x_0 \leftarrow x_1 \quad (\text{trust}(t-2) \leftarrow \text{trust}(t-1))$$
$$x_1 \leftarrow x_2 \quad (\text{trust}(t-1) \leftarrow \text{trust}(t))$$
$$x_2 \leftarrow x_{10} \quad (\text{trust}(t) \leftarrow \text{stasis\_cos}(t))$$

**Interpretación cibernética:**
En este sustrato simplificado, **confianza = proximidad al atractor**. No hay ejes múltiples de confianza (como en el kernel completo de 128 dimensiones), así que trust es simplemente una copia de stasis_cos.

La historia de 3 ticks permite detectar tendencias:
- $\text{trust}(t) > \text{trust}(t-1) > \text{trust}(t-2)$: el sistema converge.
- $\text{trust}(t) < \text{trust}(t-1) < \text{trust}(t-2)$: el sistema diverge.

**Almacenamiento:**
- $x_0, x_1, x_2 \leftarrow$ historia de trust (Bloque A, dims 0-2)

---

### **8. Paso 6: Función de Lyapunov L(t) y Derivada dL**

**Función de Lyapunov:**

$$L(t) = \alpha_L \cdot (1 - \text{stasis\_cos}(t)) + \beta_L \cdot \frac{H(t)}{H_{\max}}$$

con $\alpha_L = 0.6$, $\beta_L = 0.4$, $H_{\max} = 2.0$ bits.

**Interpretación:**
$L(t)$ es una **función de energía** que combina:
1. **Distancia al atractor:** $(1 - \text{stasis\_cos})$ es grande cuando el sistema está lejos del atractor.
2. **Entropía relativa:** $H/H_{\max}$ es grande cuando el sistema tiene alta variedad (posible inestabilidad).

**Derivada discreta:**

$$dL(t) = L(t) - L(t-1)$$

**Condición de convergencia (Teorema 2 del paper):**

$$\mathbb{E}[dL] \leq 0$$

Si $dL < 0$ en promedio, el sistema converge al atractor (la "energía" decrece).

**Almacenamiento:**
- $x_{14} \leftarrow dL(t)$ (Bloque G, dim 14)

---

### **9. Paso 7: Exponente de Lyapunov λ_max (Benettin 1D)**

**Perturbación:**

$$\delta x(t) = |\text{stasis\_cos}(t) - \text{stasis\_cos}(t-1)|$$

**Floor físico:**

$$\delta x_{\text{safe}}(t) = \max(\delta x(t), \delta x_{\text{floor}})$$

con $\delta x_{\text{floor}} = 0.001$.

**Buffer circular:**
Mantenemos $W = 10$ valores de $\delta x_{\text{safe}}$.

**Estimador de Benettin:**

$$\lambda_{\max}(t) = \frac{1}{W-1} \sum_{i=1}^{W-1} \log\left(\frac{\delta x_{\text{safe}}(t-i+1)}{\delta x_{\text{safe}}(t-i)}\right)$$

**Skip inicial:**
Durante los primeros 10 ticks, $\lambda_{\max} = 0$ (warmup).

**Interpretación cibernética:**
$\lambda_{\max}$ mide la **tasa de divergencia/convergencia** de trayectorias cercanas.

- $\lambda_{\max} < 0$: el sistema es contractivo (trayectorias convergen → atractor estable).
- $\lambda_{\max} > 0$: el sistema es expansivo (trayectorias divergen → caos o inestabilidad).
- $\lambda_{\max} = 0$: borde crítico.

En el kernel completo (128D), $\lambda_{\max}$ se calcula con el algoritmo de Benettin completo (Gram-Schmidt). Aquí usamos una aproximación 1D basada en la derivada de stasis_cos.

**Almacenamiento:**
- $x_{13} \leftarrow \lambda_{\max}(t)$ (Bloque G, dim 13)

---

### **10. Paso 8: Funcional de Viabilidad V**

**Cuatro ejes:**

$$V = \min(g, c, t, m)$$

**1. Factibilidad (g):**

$$g = 1 - \frac{B_{\text{SRAM}}}{1536}$$

donde $B_{\text{SRAM}}$ es la memoria usada (estimada en ~200 bytes).

**2. Signo de contracción (c):**

$$c = \begin{cases} 1 & \text{si } \lambda_{\max} < 0 \\ 0 & \text{si } \lambda_{\max} \geq 0 \end{cases}$$

**3. Topología (t):**

$$t = \begin{cases} 1 & \text{si } \text{Var}(\text{stasis\_cos}, W=20) < \theta_{\text{var}} \\ 0 & \text{en otro caso} \end{cases}$$

con $\theta_{\text{var}} = 0.001$.

**4. Margen (m):**

$$m = 1 - \frac{\text{excursion}_{\max}}{\varepsilon_{\text{frontier}}}$$

donde:
- $\text{excursion}_{\max} = \max_{i \in W} |\text{stasis\_cos}(t-i) - \overline{\text{stasis\_cos}}|$
- $\varepsilon_{\text{frontier}} = \sqrt{2(1 - \theta_{\text{viable}})} = \sqrt{2(1 - 0.70)} = 0.7746$

**Interpretación cibernética:**
$V$ es un **certificado de viabilidad** que combina:
- **g**: ¿tenemos recursos? (SRAM)
- **c**: ¿el sistema converge? (λ_max < 0)
- **t**: ¿el sistema es estable? (varianza baja)
- **m**: ¿qué tan lejos estamos del borde de viabilidad? (margen)

Si $V > 0$, el sistema es viable. Si $V = 0$, al menos un eje falló.

---

### **11. Paso 9: Control φ↓ (Ajuste de PWM)**

**Ley de control:**

$$\text{PWM}(t) = \begin{cases} \text{PWM}(t-1) + \Delta_{\text{PWM}} & \text{si } dL > 0 \\ \text{PWM}(t-1) - \Delta_{\text{PWM}} & \text{si } dL < 0 \\ \text{PWM}(t-1) & \text{si } dL = 0 \end{cases}$$

con $\Delta_{\text{PWM}} = 3$, $\text{PWM} \in [10, 245]$.

**Interpretación cibernética:**
Este es un **controlador bang-bang suavizado** que ajusta el LED blanco (actuador φ↓) en respuesta a la derivada de Lyapunov.

- Si $dL > 0$: la "energía" aumenta (sistema se aleja del atractor) → aumentar PWM (más luz → más señal → corregir).
- Si $dL < 0$: la "energía" disminuye (sistema converge) → reducir PWM (menos luz → evitar sobre-actuación).

El paso $\Delta_{\text{PWM}} = 3$ es pequeño para evitar oscilaciones. Los límites $[10, 245]$ evitan saturación (LED completamente apagado o encendido).

**Almacenamiento:**
- $x_9 \leftarrow \text{PWM}(t) / 255$ (Bloque E, dim 9, normalizado)

---

### **12. Paso 10: Actualización de LEDs (Visualización)**

**Mapeo de stasis_cos a colores:**

| stasis_cos | Color | Significado |
|------------|-------|-------------|
| ≥ 0.95 | Verde | Punto dulce (stasis) |
| 0.85 - 0.95 | Verde + Amarillos tenues | Cerca del atractor |
| 0.79 - 0.85 | Amarillos full | PSI (precaución) |
| 0.70 - 0.79 | Rojos + Amarillos | Pre-viable |
| < 0.70 | Rojos parpadeantes | No viable |

**Interpretación cibernética:**
La barra de LEDs es una **interfaz algedónica** que comunica el estado de viabilidad al operador humano (S5). Es el canal φ↑ de salida (hacia el observador).

### **13. Paso 11: Verificación de viable_full + A_auto**

**Condición de viabilidad completa:**

$$\text{viable\_full} = (V > 0) \wedge (\text{stasis\_cos} \geq \theta_{\text{viable}})$$

**Mecanismo A_auto (degeneración):**

$$\text{degen\_counter} = \begin{cases} \text{degen\_counter} + 1 & \text{si } \text{stasis\_cos} < \theta_{\text{viable}} \\ 0 & \text{en otro caso} \end{cases}$$

Si $\text{degen\_counter} \geq \tau_{\text{degen}} = 50$ ticks (1 segundo):

- Intento 1-2: recalibrar automáticamente (L2 autónomo).
- Intento 3: escalar a S5 (L3, requiere humano) → parpadeo rojo + espera.

**Interpretación cibernética:**
A_auto es el **mecanismo de homeostasis** que detecta pérdida prolongada de viabilidad y activa protocolos de recuperación. Es análogo al canal algedónico en Beer: dolor sostenido → acción correctiva.

2. loop_delta_ms ≤ 20ms
3. stasis_cos ≥ 0.85

Si las 3 condiciones se cumplen → governed = true.

### **15. Síntesis: Cómo Emerge el Atractor**

El ciclo completo implementa un **sistema dinámico discreto** en $\mathbb{R}^{16}$:

$$\mathbf{x}(t+1) = f_0(\mathbf{x}(t)) + \sigma \cdot \eta(t)$$

donde:
- $f_0$: la dinámica determinista (los 14 pasos)
- $\sigma \cdot \eta(t)$: perturbación estocástica (ruido de sensores, variaciones de luz)

**Mecanismo de convergencia:**

1. **Lectura de sensores** (Paso 1): el sistema percibe el entorno.
2. **Cálculo de error** (Paso 2): compara con la referencia (ratio calibrado).
3. **Medición de entropía** (Paso 3): evalúa la diversidad interna.
4. **Proximidad al atractor** (Paso 4): calcula stasis_cos.
5. **Función de Lyapunov** (Paso 6): evalúa la "energía" del sistema.
6. **Control** (Paso 9): ajusta el actuador para reducir $L$.

**Condición de estabilidad:**

Si $\mathbb{E}[dL] \leq 0$ (Teorema 2), el sistema converge al atractor. En la práctica:
- El LED blanco se ajusta para mantener el ratio $r(t) \approx r_{rest}$.
- La entropía $H(t)$ se mantiene cerca de $H_{rest}$.
- stasis_cos → 1 (el sistema se alinea con el atractor).

**Emergencia del atractor:**
El atractor no está "programado" explícitamente. **Emerge** de la interacción entre:
- La dinámica de control (Paso 9)
- La función de Lyapunov (Paso 6)
- La retroalimentación sensorial (Pasos 1-4)

Es un **atractor auto-organizado**, no un punto fijo predefinido.

### **16. Conexión con la Teoría Cibernética**

**Beer (VSM):**
- S1 (Operations): sensores + actuadores (fotoresistores + LED)
- S2 (Coordination): entropía H(t) como medida de coordinación
- S3 (Control): ley de control PWM (Paso 9)
- S4 (Intelligence): stasis_vec (memoria del atractor)
- S5 (Policy): trust + governed (Bloque A)

**Ashby (Requisite Variety):**
El sistema tiene variedad interna (4 organelos, 16 dimensiones) para absorber la variedad externa (perturbaciones de luz). Si la variedad externa excede la interna, el sistema pierde viabilidad (A_auto se activa).

**Lyapunov (Estabilidad):**
La función $L(t)$ certifica convergencia. Si $dL < 0$ en promedio, el atractor es estable. El exponente $\lambda_{\max}$ cuantifica la tasa de convergencia.

**Segunda Cibernética (Observer):**
El operador humano (S5) observa la barra de LEDs (Paso 10) y decide si el sistema es viable. El observador es **constitutivo**: su interpretación de stasis_cos define la viabilidad.

### 1. Los 64 bytes: el costo de *saber dónde estás*

El state vector de vOS-nano son 16 floats × 4 bytes = **64 bytes**. Pero no son 64 bytes cualesquiera. Representan:

| Bloque | Dimensiones | Qué codifica |
|--------|-------------|--------------|
| A (identidad) | 0-3 | trust(t-2..t), governed |
| C (entropía) | 4-6 | H(t), H_rest, entropy_phase |
| E (señales) | 7-9 | φ↑_p, φ↑_a, φ↓ |
| F (atractor) | 10-12 | stasis_cos, stasis_ratio, stasis_H |
| G (convergencia) | 13-15 | λ_max, dL, lifecycle |

**64 bytes = la memoria mínima para que un sistema sepa si está viable.**

#### Comparación con sistemas no-cibernéticos:

**Sistema sin gobernanza cibernética** (ej: un microcontrolador típico con PID):
- Estado: 3-5 variables (setpoint, error, integral, derivative, output)
- Memoria: ~20 bytes
- **No sabe si es viable**, solo sabe si está "cerca del setpoint"

**Sistema con gobernanza cibernética completa** (vOS-nano):
- Estado: 16 variables
- Memoria: 64 bytes
- **Sabe si es viable** (stasis_cos ≥ 0.70), **sabe por qué** (qué eje de V está fallando), **sabe cómo recuperarse** (λ_max < 0 → contractivo)

**El costo: 44 bytes adicionales = la diferencia entre "control" y "viabilidad".**

Un PID te dice "estás a 2.3 unidades del objetivo".  
vOS-nano te dice "estás en el atractor, contractivo, con margen de ruido 0.71, y tu entropía es 0.47 bits sobre un máximo de 2.0 bits".

**Eso son 44 bytes de "consciencia cibernética".**

### 2. Los 20ms: el costo de *pensar en tiempo real*

Cada tick de 20ms ejecuta 14 pasos de cómputo:

```
1. Leer sensores + EMA              ~2ms (ADC + 2× multiply-accumulate)
2. Calcular ratio                   ~0.1ms (división)
3. Actualizar bins → H(t)           ~1ms (4 bins, log₂)
4. Calcular stasis_cos              ~1ms (2D cosine, sqrt, normalize)
5. trust(t) = stasis_cos            ~0.01ms (asignación)
6. dL = L(t) - L(t-1)              ~0.1ms (2× multiply + subtract)
7. λ_max (Benettin 1D)              ~2ms (10 iteraciones, log)
8. V = min(g, c, t, m)             ~3ms (varianza, excursion, 4× compare)
9. Ajustar PWM                      ~0.1ms (constrain + analogWrite)
10. Actualizar LEDs                 ~0.5ms (5× analogWrite)
11. Verificar viable_full + A_auto  ~0.1ms (compare + counter)
12. Serial log (cada 10 ticks)      ~0.5ms promedio
13. H1 counter                      ~0.01ms
14. covenant_check                  ~0.1ms (3 condiciones)
─────────────────────────────────────────────────────────────
TOTAL:                              ~12.5ms de cómputo + 7.5ms de margen
```

**12.5ms = el tiempo que le toma al sistema *certificar su propia viabilidad*.**

#### Comparación con sistemas no-cibernéticos:

**Sistema sin gobernanza cibernética** (ej: Arduino con PID):
- Loop: ~1ms (leer sensor, calcular PID, escribir output)
- **No certifica nada**, solo reacciona

**Sistema con gobernanza cibernética** (vOS-nano):
- Loop: ~12.5ms (leer, calcular, certificar, actuar)
- **Certifica viabilidad en cada tick**

**El costo: 11.5ms adicionales = la diferencia entre "reaccionar" y "certificar".**

Un PID reacciona en 1ms.  
vOS-nano reacciona **y certifica** en 12.5ms.

**Eso son 11.5ms de "auditoría cibernética en tiempo real".**

### 3. ¿Qué significa esto en términos de "impuesto de gobernanza"?

#### Costo computacional:

| Sistema | CPU (20ms) | RAM (64 bytes) | Sabe si es viable |
|---------|------------|----------------|-------------------|
| PID básico | 5% | 20 bytes | ❌ No |
| PID + logging | 15% | 40 bytes | ❌ No |
| **vOS-nano** | **62.5%** | **64 bytes** | **✅ Sí** |

**El impuesto de viabilidad: 62.5% del CPU + 64 bytes de RAM = la capacidad de saber si estás vivo.**

#### Costo en términos de "oportunidad perdida":

En 20ms, un sistema sin gobernanza podría hacer:
- 20 iteraciones de PID
- 10 lecturas de sensor + procesamiento
- 5 cálculos complejos (FFT, filter, etc.)

En 20ms, vOS-nano hace:
- 1 iteración de gobernanza completa (certificación + acción)

**El costo de oportunidad: 19 iteraciones de "hacer cosas" vs. 1 iteración de "saber si puedes seguir haciendo cosas".**

### 4. ¿Por qué vale la pena pagar este impuesto?

#### Escenario 1: Sistema sin gobernanza cibernética

Un dron con PID vuela hacia un objetivo. De repente, un viento fuerte lo desvía. El PID corrige, pero no sabe que:
- La batería está al 15% (recurso crítico)
- La entropía del sistema aumentó (inestabilidad)
- El atractor se desplazó (el objetivo ya no es alcanzable)

El dron sigue volando hasta que se queda sin batería y cae. **Nunca supo que era no-viable.**

#### Escenario 2: Sistema con gobernanza cibernética (vOS-nano)

El mismo dron con vOS-nano vuela hacia el objetivo. El viento fuerte lo desvía. En 20ms:
- stasis_cos cae a 0.65 (< 0.70 → no-viable)
- V = min(g=0.15, c=0, t=1, m=0.3) = 0 (contracción falló)
- λ_max = +0.02 (expansivo → divergente)
- dL = +0.05 (Lyapunov aumenta → alejándose del atractor)

El sistema **sabe que es no-viable en 20ms**. Activa A_auto:
- Recalibra stasis_vec (nuevo atractor considerando viento)
- Reduce PWM (ahorra batería)
- Emite φ↑ (pide ayuda a S5)

El dron aterriza de emergencia. **Sobrevive porque supo que era no-viable.**

### 5. La pregunta profunda: ¿cuánta gobernanza puedes pagar?

#### Regla empírica:

**El impuesto de viabilidad debe ser < 50% del presupuesto computacional total.**

Si tu sistema tiene 100ms de presupuesto:
- 50ms para "hacer cosas" (S1: operaciones)
- 50ms para "saber si puedes seguir haciendo cosas" (S3/S4: gobernanza)

vOS-nano usa 12.5ms de 20ms = 62.5%. **Está al límite, pero es viable.**

#### ¿Por qué no 100%?

Porque si gastas todo el tiempo en gobernanza, no tienes tiempo para **operaciones**. Un sistema que solo se audita a sí mismo pero no hace nada es un sistema muerto.

#### ¿Por qué no 10%?

Porque si gastas muy poco en gobernanza, no tienes **resolución suficiente** para detectar no-viabilidad. Un sistema que solo se audita cada 1 segundo no puede reaccionar a perturbaciones de 20ms.

**El punto óptimo: ~30-50% del presupuesto computacional dedicado a gobernanza.**

vOS-nano está en 62.5% porque es un sistema mínimo (ATmega328P). En un sistema más grande (Raspberry Pi, servidor), el impuesto sería ~5-10% del presupuesto total.

### 6. La síntesis: qué significan 20ms y 64 bytes

**20ms = el tiempo mínimo para certificar viabilidad en un sistema cibernético.**

No es "tiempo de CPU". Es **tiempo de consciencia cibernética**: el tiempo que le toma al sistema preguntarse "¿soy viable?" y obtener una respuesta certificada.

**64 bytes = la memoria mínima para representar el estado de viabilidad.**

No es "RAM usada". Es **el mapa del atractor**: la representación comprimida de "dónde estoy en el espacio de viabilidad" y "hacia dónde me muevo".

**vOS-nano paga el 62.5% del CPU y 64 bytes de RAM para obtener gobernanza cibernética completa.**

Es el **mínimo viable** para un sistema que quiere saber si es viable.

Q:
En el contexto de **EXP-NB-01 (vOS-nano)**, un **organelo** es cada una de las **4 categorías discretas** en las que se cuantiza la lectura del fotoresistor principal (A0) para calcular la entropía H(t).

## Definición formal (addendum_v1.vsm §GAP_NB_01)

```
organelo_0:  A0 ∈ [0,   255]   → p₀ = fracción de ticks en este rango (ventana W=10)
organelo_1:  A0 ∈ [256, 511]   → p₁
organelo_2:  A0 ∈ [512, 767]   → p₂
organelo_3:  A0 ∈ [768, 1023]  → p₃

H(t) = -∑ᵢ pᵢ · log₂(pᵢ)    para pᵢ > 0
H_max = log₂(4) = 2.0 bits
```

## Interpretación cibernética

El término "organelo" es una **metáfora biológica** — en biología celular, los organelos son las sub-unidades funcionales de una célula (mitocondria, núcleo, retículo endoplásmico). En vOS-nano:

| Concepto biológico | Equivalente en vOS-nano |
|---|---|
| Célula | El kernel (state vector ℝ¹⁶) |
| Organelos | Las 4 categorías de activación del sensor A0 |
| Activación metabólica | Lectura ADC en un rango específico |
| Entropía metabólica | H(t) sobre la distribución de activaciones |

## Función en el sistema

Los organelos permiten calcular **H(t)** — la entropía de Shannon sobre la distribución de activaciones del sensor en una ventana deslizante de W=10 ticks (200ms). Esto captura:

- **H ≈ 0**: el sensor está siempre en el mismo rango → sistema estable, baja variedad
- **H ≈ 2.0 bits**: el sensor visita todos los rangos uniformemente → alta variedad, posible inestabilidad
- **H_rest**: la entropía calibrada en Phase 1 (típicamente 0.5-1.0 bits en stasis)

El vector de stasis es entonces **stasis_vec = [stasis_ratio, stasis_H]** ∈ ℝ², y la proximidad al atractor se mide como el coseno entre el vector actual [ratio(t), H(t)] y el vector de referencia calibrado.

// Paso 3 del computation_order:

else if (a0 <= 511)  organelo = 1;
else if (a0 <= 767)  organelo = 2;
else                 organelo = 3;

bin_idx = (bin_idx + 1) % W_H_BINS;  // W_H_BINS = 10
